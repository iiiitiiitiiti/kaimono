## 003. 追加履歴は別の置き場に品物と分けて書き、古い物は開いたときに消す

- 日付: 2026-11-15
- 対象: `src/useList.ts`・`src/model.ts`・`firestore.rules`（`lists/{鍵}/log`）

### 決定

足すたびに `lists/{鍵}/log` へ1件書く。品物の保存とは1回の書き込みにまとめず、別に書く。残すのは90日で、アプリを開いて保存先から中身が届いたときに古い物を消す。

### 背景

「よく買う物」の記録（history）は品名ごとの回数しか持たず、リストから消すと「いつ誰が何を足したか」が残らなかった。ユーザーは「足した記録の一覧」を「直近90日」で選んだ。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| 品物と同じ1回の書き込みにまとめる | rules が出る前や履歴の検査で落ちたとき、品物まで足せなくなる。履歴は品物より軽い情報なので巻き添えにしない |
| history に時刻の配列を足す | 文書が品名ごとなので、日ごとに並べるには全文書を読んで組み直すことになる。配列も際限なく伸びる |
| Firestore の期限付きで自動に消す仕組み（TTL） | Console か gcloud での設定が要り、手元のコードだけで完結しない |
| 照会で90日以内だけ読む | 送信待ちの時刻は照会の条件に当たらず、足した直後に一覧へ出ないおそれがある。2人で90日なら全部読んでも数百件 |

### 影響

- 取り消しで戻した物・直した物は記録しない。足した時だけ書く。
- 消すのは1回に400件まで。それを超える古い物は次に開いたときに消える。
- 履歴が読めなくてもリスト全体は止めない（読み込み失敗は画面に出さない）。

### 検証

- 日ごとの並べ方・90日の切り捨ては `tests/model.test.ts` で確かめた。
- 画面は本物の CSS でスマホ幅の見本を作り、長い品名でも崩れないことを見た。
- 実機で足した物が一覧に出るかは、rules のデプロイ後にユーザーが確かめる（未確認）。
