## 007. 送った更新のお知らせは、Actions の手動実行で書き換える

- 日付: 2026-11-25
- 対象: `.github/workflows/edit-discord.yml`・`.github/notify-discord.sh`・`.github/workflows/deploy.yml` の `notify`

006 の更新のお知らせを、あとから書き換えられるようにする。足した品物の知らせ（005）は対象外。

### 決定

お知らせを送るときに Discord が返す投稿の番号を、Actions の成果物 `discord-message`（90日残る）に置く。書き換えは手動で動かす流れ `edit-discord.yml` が受け持つ。書き換える投稿（`last` か投稿のリンク）と、書き換えた後の変わった点（1行に1つ）を渡す。`last` なら成果物から最後に送った投稿を探す。前の文は引き継がないので、残す行もすべて書く。見出しと最後の一言は送るときと同じ形で付け直す。

本人が Claude に「最後の投稿を直して」や投稿のリンクを渡したら、Claude は新しい文面を akapen スキルへ通す（送るときと同じ・2026-11-25 本人の依頼）。本人に見せて承認を得てから次を動かす。

```
gh workflow run edit-discord.yml -f message=last -f notes="1行目
2行目"
```

送らずに中身だけ確かめるときは `-f dry_run=true` を足す。

2026-11-25 の同日、本人の決定で、送る手順と書き換えの流れをかけいぼの版（kakeibo のコミット 226fb93）にそろえた。`notify-discord.sh` はかけいぼと同じ中身で、ツール名は流れのファイルの `APP_NAME` で変える。最初にかいもので作った `discord-edit.yml` は消した。

### 背景

2026-11-25 に本人がメイン経由で「前に送った投稿をあとから書き換える」機能を頼んだ。かいものの送り先は GitHub のシークレットにあり手元からは読めないので、書き換えも GitHub の中で動かす必要がある。同じ日にかけいぼ・ふたりのレシピ帳も同じ機能を入れた。かけいぼ版にだけ安全策があったので、本人はかけいぼ版にそろえることを選んだ。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| かいもので最初に作った版（`discord-edit.yml`）を残す | かけいぼ版の安全策が無い。書き換える前に今の文を見せない・番号を残せないと公開が失敗になる・送り先の URL の末尾を整えない。リポごとに中身が違うと直すときに3つをそろえられない |
| 投稿の番号をリポにコミットして残す | notify ジョブに書き込みの権限が要り、そのコミットがまた公開の流れを動かす |
| 投稿の番号をリポの変数（Actions variables）に残す | Actions が持つ鍵では変数を書き換えられず、別の鍵を本人に作ってもらう手間が要る |
| 書き換えを手元の PC から送る | 送り先の URL が手元に無い。URL を手元に置くと漏れる場所が増える |
| リンクだけで書き換え、番号は残さない | 「最後の投稿を直して」に応えられない。Discord のウェブフックは送った投稿の一覧を返さない |

### 影響範囲

- `notify-discord.sh` はかけいぼ・動物園・水族館ログと同じ中身にする。直すときは3つのリポをそろえる。
- 書き換える前に今の投稿の文をログに出す。番号だけでは、どの投稿を直すのか見分けられないため。
- 番号を残す手順が失敗しても公開は成功にする。失敗にすると次の公開で同じお知らせをもう一度送るため。
- 送り先の URL の末尾の `/` と `?thread_id=` などは、行き先ごとに付け直す。
- 書き換えられるのは、このウェブフックが送った投稿だけ。ほかの投稿は Discord が断り、流れが失敗で終わる。
- 90日より前の投稿は `last` で探せない。リンクを渡せば書き換えられる。

### 検証

- 2026-11-25 にかけいぼ版へそろえたあと、手元の bash で `DRY_RUN=1` を使って試した。リンク・`last`・読めないリンク・空の文・送り先が無いときの失敗・お知らせの無い公開を確かめた。
- 偽の curl に差し替えて試した。送ると `?wait=true` で送り、番号をファイルに書く（URL の末尾の `/` と `?thread_id` は付け直す）。書き換えは今の文を読んでから `PATCH …/messages/番号` へ送る。
- 本物の Discord での書き換えは、お知らせを1度送るまで試せない（2026-11-25 時点でまだ1件も送っていない）。
