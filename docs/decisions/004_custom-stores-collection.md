## 004. 自分で入れたお店は別の置き場に1店1件で持つ

- 日付: 2026-11-16
- 対象: `src/useList.ts`・`src/model.ts`・`src/App.tsx`・`firestore.rules`（`lists/{鍵}/stores`）

### 決定

2人が自分で入れたお店は `lists/{鍵}/stores/{店名の ID}` に1店1文書（`name` だけ）で持つ。品物・よく買う物・追加履歴のお店は今までどおり店名の文字列で持ち、rules はお店の名前を1〜20字の長さだけで見る。

### 背景

お店は固定の10種だけだった。ユーザーから「お店にカスタム入力が欲しい」と頼まれ、10種は残して足す・メニューで消せる・名前の変更は要らない、と決まった。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| 置き場を作らず、品物とよく買う物に出てくるお店から一覧を毎回作る | よく買う物は品名ごとにお店を1つしか持たず、足すたび・直すたびに上書きされる。業務スーパーで足した物を次にスーパーで足すと、消していない業務スーパーが一覧から消える（fable-advisor の指摘） |
| 1つの文書に店名の配列で持つ | rules は配列の要素を1つずつ確かめられない。1店1文書なら、ほかの置き場と同じ形で名前を確かめられる |
| rules で item のお店が一覧にあるかを確かめる | 書き込みごとに読み取りが1回増える。消したのと行き違いで足した物が保存できなくなる |

### 影響

- 品物を足す・直すときに、自分のお店がまだ一覧に無ければ別に書き足す。保存できなくても品物は足せる（003 の追加履歴と同じ考え）。
- 消すときは一覧から外し、そのお店の品物とよく買う物を「その他」へ書き換える。書き換えないと、同じ名前を入れ直したときに古い品物がそのお店へ戻る。追加履歴は記録なので書き換えない。
- rules を先にデプロイしてからアプリを出す。緩める向きなので、古い版のアプリでも壊れない。
- 古い版のアプリ（更新前の端末）は知らないお店を「その他」として出す。そのまま直すと「その他」で上書きされる。新しい版はアプリを裏へ回したときに入る。
