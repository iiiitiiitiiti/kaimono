## 005. Discord への知らせは足したスマホから送り、URL はリストの設定として2人で共有する

- 日付: 2026-11-25
- 対象: `src/useList.ts`・`src/model.ts`・`src/App.tsx`・`index.html`・`firestore.rules`（`lists/{鍵}/settings/notify`）

### 決定

品物を足したとき、足したスマホのアプリが Discord のウェブフックへ直接送る。ウェブフックの URL は `lists/{鍵}/settings/notify` の `discord` に1件だけ置き、2人で共有する。メニューの「Discord に知らせる」で入れる・試しに送る・止めるができる。

### 背景

ユーザーから「買いたいものを追加したとき、Discord の webhook で通知が行くようにできないか」と頼まれた。送り方と URL の置き場は、ユーザーが下の表の推薦どおりに選んだ。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| Firebase の自動処理（Cloud Functions）が品物の追加を見て送る | 従量課金プランへの切り替えとカードの登録が要る。電波の無いところで足した物も必ず届く利点はあるが、ユーザーは無料ですぐ作れる方を選んだ |
| URL を端末ごとに覚える（localStorage） | 保存先の決まりは変えずに済むが、2人がそれぞれ同じ URL を入れる手間がかかる。ユーザーは共有を選んだ |
| URL をアプリのコードに書き込む | 公開しているコードからだれでも読め、チャンネルへ勝手に書き込まれる |

### 影響

- URL はリストの鍵を知っている人（2人）なら読める。鍵が漏れたら URL も漏れるので、そのときは Discord でウェブフックを消して作り直す。
- 電波が無くて送れなかった知らせは、アプリを開いている間につながれば送る。つながる前にアプリを閉じた分は届かない（ユーザーは承知のうえでこの案を選んだ）。
- 送る文の記号は `\` を付けて送り、`allowed_mentions` を空にする。品名に `@everyone` や `**` が入っても、呼び出しや太字にならない。
- 「始める」を押すと先に試しの1件を送り、届いたときだけ2人の設定にする。間違った URL を共有しないため。
- `index.html` の CSP の `connect-src` に Discord を足した。足す前は送信が「Failed to fetch」で弾かれた（見えない Chrome で確かめた）。
- rules を先にデプロイしてからアプリを出す。先にアプリを出すと、試しの1件は届くのに設定の保存だけが失敗する。
- 取り消しの付いたワンタップの追加を取り消しても、送った知らせは消えない。
