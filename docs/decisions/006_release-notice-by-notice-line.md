## 006. 公開の知らせは、コミットの「お知らせ:」の行だけを Discord へ送る

- 日付: 2026-11-25
- 対象: `.github/workflows/deploy.yml` の `notify`・`.github/notify-discord.sh`・GitHub のシークレット `DISCORD_WEBHOOK_URL`

足した品物の知らせ（005）とは別の仕組みで、送り先のウェブフックも別にする。

### 決定

公開が成功したあと、コミットの本文にある「お知らせ: 〜」の行だけを集め、Discord のウェブフックへ箇条書きで送る。その行が無い公開では送らない。行は公開する Claude が使う人の言葉で書く。拾う範囲は前に公開が成功したコミットから今回までにし、続けて push して前の公開が取り消されても知らせが抜けないようにする。

### 背景

2026-11-25 にユーザーが「2人で使うツールで機能にアップデートが入ったときは webhook で Discord にお知らせを入れたい」と頼んだ。対象はかいもの・かけいぼ・動物園・水族館ログ・ふたりのレシピ帳の4つ（ユーザーが決めた）。このうち GitHub Pages の3つはこの仕組みで送る。ふたりのレシピ帳は Artifact なので、公開し直した Claude が本人の承認を得てから送る。かけいぼは 11-22 から `feat:`・`fix:` の1行目を全部送っていた。ほかのツールではコミットの1行目が英語だったり、部品の入れ替えのような使う人に関係ない `fix:` が多かったりする。ユーザーは比べたうえで「お知らせ用の1行を付けた更新だけ」を選び、かけいぼもこの形にそろえることにした。チャンネルは4つで同じにし、ウェブフックはツールごとに分ける（同日ユーザー指定）。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| `feat:`・`fix:` の1行目を全部送る（かけいぼの 11-22 の形） | 部品の更新のような使う人に関係ない直しまで届く。動物園・水族館ログでは `fix: bump vite to 7.3.7 ...` のような英語の文がそのまま届く |
| その push のコミット（`github.event.commits`）だけを見る | 公開の流れは `cancel-in-progress: true` なので、続けて push すると前の公開が取り消され、その分の知らせが届かない |
| 更新履歴のファイルを別に書いて送る | 公開のたびにファイルを直す手間が増える。コミットに1行足せば足りる |
| Discord のウェブフックの GitHub 用の受け口（URL の末尾 `/github`） | すべての push が英語のコミット一覧として流れ、公開の成否とも関係なく出る |

### 影響範囲

- 公開する窓口は、使う人に知らせたい変更のコミットの本文に `お知らせ: 〜` を1行書く。1行目（件名）ではなく本文に書く。全角の「：」でもよい。同じ文は1回だけ、15行まで送る。
- 送る中身はコミットの文面だけ。記録や保存先の中身は送らない。メンションは `allowed_mentions` で無効にする。
- 手動実行（workflow_dispatch）の公開でも送る。手動実行の成功で「前の成功」が進むので、送らないとその前に取り消された分のお知らせが抜けるため。
- 前に成功した公開は `gh run list --status success` で探すので、notify ジョブに `actions: read` の権限が要る。見つからないとき（初めての公開・履歴を書き換えたとき）は、その push のコミットだけを見る。
- 送り先の URL は GitHub のシークレット `DISCORD_WEBHOOK_URL`。リポ・記録・チャットに書かない。無ければ何もせず成功で終わる。
- 送る手順は `.github/notify-discord.sh`。かいもの・かけいぼ・動物園・水族館ログで同じ中身なので、直すときは3つのリポをそろえる。

### 検証

- 2026-11-25 に作り物のコミットで手元の bash から試した（`DRY_RUN=1` で送らずに中身を出す）。お知らせの行だけを古い順に拾う・本文の全角の「：」と前後の空白と CRLF・同じ文は1回・16行あれば15行・記号の逃がし・空の「お知らせ:」は拾わない・範囲にお知らせが無ければ送らない・前の公開が祖先でないときは push のコミットを見る・URL が空なら送らない、を確かめた。
- 本物のリポで `gh run list` が前に成功した公開のコミットを返すことを確かめた。
