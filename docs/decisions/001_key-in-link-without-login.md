## 001. ログインなしで鍵つきリンクで開く

- 日付: 2026-11-04
- 対象: 保存先の守り方（`firestore.rules`・`src/App.tsx` の鍵の読み込み・`vite.config.ts` のマニフェスト）

### 決定

Firestore のリストを `lists/{鍵}/…` に置き、rules は鍵の SHA-256 だけを照合する。鍵はリンクの `#k=` に載せて2人に渡し、URL から消さない。
作る人の手作業がゼロで、相手はリンクを開くだけで使える。守る対象が買い物の品目なので、この重さで足りる。

### 背景

置き場は GitHub Pages に決まった（ユーザー選択）。2人で同じリストを見るには共有の保存先と、第三者に書かせない仕組みが要る。相手は Claude 等のアカウントを持たない前提。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| Artifact の db | 相手にも Claude のアカウントと招待が要り、毎回 claude.ai を通る（置き場の質問でユーザーが Pages を選んだ） |
| Firebase Auth の世帯共有アカウント（動物園ログと同じ合言葉方式） | サインイン方法の有効化に Firebase Console の手作業が要る（CLI では有効化できない）。2人が合言葉を覚えて打つ必要がある |
| 鍵を端末に保存して URL から消す | iPhone はホーム画面のアプリと Safari で保存場所が別で、ホーム画面から開くと鍵が無くなる |
| マニフェストを置く | iPhone は manifest の `start_url` で起動し、URL の鍵が落ちる。見た目は `apple-*` の meta と `apple-touch-icon.png` で代える |

### 影響範囲

- 鍵が漏れたら誰でも読み書きできる。失効は「新しい鍵を作り rules を再デプロイし、リンクを送り直す」（手順は `docs/DESIGN.md`）
- 鍵の本体は、この PC の `.secret-key`（git 管理外）だけが持つ

### 検証

- 正しい鍵で REST から読み書きでき、別の鍵では 403 になることを確かめた
- 公開版で鍵つきリンクからリストが開くことを確かめた
- iPhone で Safari から開いてホーム画面に置き、アプリを閉じて開き直してもリストが出ることをユーザーが確かめた（2026-11-04）。ホーム画面から開いて「届いたリンクを開いて」の画面が出るようになったら、この判断の前提が崩れている

### 関連ファイル

- `firestore.rules`
- `src/App.tsx`（`loadKey`）
- `vite.config.ts`（`manifest: false`）
- `index.html`
